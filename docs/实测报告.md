## 2. 已实测跑通的项目

### 2.1 koboldcpp（LLM）— ✅ 通过
- 单文件 `koboldcpp.exe`（594MB）直接运行，自带 `koboldcpp_cublas.dll`
- **实测日志**：`ggml_cuda_init: found 1 CUDA devices ... compute capability 6.1, VMM: yes`
- 加载 Qwen2.5-0.5B-Instruct Q4_K_M（491MB），100 层全部 offload 到 GPU
- **benchmark 结果**：
  - prompt 处理：`10266.67 tok/s`
  - **生成：`132.45 tok/s`**
  - 后端：`koboldcpp_cublas.dll`，CUDA Graph 正常建立（nodes=825）
- 结论：llama.cpp 生态在 Pascal 上**开箱即用**，无需任何 patch 即可获得可用速度。

### 2.2 CrispASR（ASR + TTS 统一 C++ runtime）— ✅ 通过
- Windows CPU 便携包（9.5MB）解压即用，`crispasr.exe --version/--help` 正常（MSVC 编译，v0.8.54）
- **TTS 实测**：Kokoro 82M Q8，`--tts "The quick brown fox jumps over the lazy dog."` → 生成 `hello.wav`（3.2 秒 / 24kHz / 152KB），exit 0
- **ASR 实测**：whisper base 模型转写上面生成的 wav → 正确识别出句子（个别词因缺 g2p 字典有误），exit 0
- **CPU 性能**：3.2 秒音频转写耗时 9.98 秒（**0.3x realtime**），印证长文"CPU 不够用"的判断
- 重要发现：
  - 内置 `-m auto` 自动下载走 HF 主站，在本网络环境**全部 502 失败**，需手动用 `hf-mirror.com` 镜像下载到 `%USERPROFILE%\.cache\crispasr`
  - 其 **CUDA 12.6 构建明确支持 Pascal/Volta**（`cuda126.zip`），CUDA 13 构建仅支持 Turing+
  - 一个二进制同时支持 ASR + TTS + 翻译 + 说话人分离，是"大一统"路线的候选

### 2.3 通用网络注意（实测）
- `huggingface.co` 主站与 GitHub release CDN 在本网络环境经常 **502**
- 可用替代：`hf-mirror.com`（模型）、`ghproxy.net`（GitHub release，支持断点续传）
- 这是"能不能下载到模型"的实际障碍，与项目本身无关

## 4. 初步结论（基于已实测数据）

1. **Pascal 上 LLM 完全可用**：koboldcpp 零配置 132 tok/s（0.5B Q4）；pascallama / minicpm5 / bonsai2 的补丁能进一步提速，且有与本机几乎一致的环境样板。
2. **TTS 有可用 C++ 方案**：CrispASR（Kokoro）已跑通；qwentts.cpp 可编译出 sm_61 原生二进制；audio.cpp 有 Windows CUDA 预编译包（下载中）。
3. **ASR 用 CPU 不够（0.3x realtime）**，需 CUDA 版；whisper.cpp / CrispASR CUDA126 / CTranslate2 INT8 都是可行路线。
4. **许可红线**：ilaria-s2.cpp（Fish Research License）不可商用；koboldcpp 是 AGPL；其余 MIT/Apache 可放心用。
5. **网络是主要摩擦点**：模型/二进制下载频繁 502，需镜像；这不影响项目本身质量。
